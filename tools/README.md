# tools/ — 「変えたが、結果は変わっていない」を機械に言わせる道具

リファクタや作り直しのあとで一番言いにくいのは **「意味論は 1 ビットも変わっていない」** です。
self_test の出力を目で追うのでは足りません:

- 速度行が実行ごとに動く
- 未シードな乱数が混ざる（保持率が 88.7% ↔ 88.5% と揺れる、など）
- そもそも self_test が **表示していない数** が大半

そこで、二つの版に同じ固定入力を食わせて、出てきた数を**全部**ビット単位で突き合わせます。

## 使い方

```bash
python tools/ab_check.py                     # 作業ツリー vs main
python tools/ab_check.py --rev HEAD~1        # 作業ツリー vs 一つ前のコミット
python tools/ab_check.py --ref /path/to/old  # git を使わず任意のディレクトリと
python tools/ab_check.py --device cpu        # 装置指定（既定: あれば cuda）
python tools/ab_check.py --negative-control  # 検査に歯があるかを検査する
```

終了コード 0 = 完全一致 / 1 = 差分あり。中身は 2 本のスクリプトです。

- `ab_dump.py <repo_dir> <out.npz> <cpu|cuda>` — 指定した版を import して固定入力のバッテリを
  走らせ、出てきた数を全部 `.npz` に落とす。乱数は numpy `default_rng(固定シード)` だけで、
  torch の RNG も時刻も使わない ⟹ **差が出たらそれはコードの差**。
- `ab_cmp.py <a.npz> <b.npz>` — ビット単位で比較。浮動小数は値でなく**ビットパターン**で
  比べるので最下位 1 ビットの差も見逃さない（NaN の位置も一致を要求する）。

## 何を比べているか

| 対象 | 内容 |
|---|---|
| CD 符号表 | `cd_omega(M)`, M = 1…16 |
| 配線表 | `wiring_tensor` の `cd` 全次元・`cyclic` 4 種 |
| スカラー全域算術 | `tot_mul` / `tot_add` / `tot_div` を 12 値 × 8 旗の**全ペア 9,216 通り** |
| 入口の税関 | NaN・±Inf・非正規数・宣言ドメイン (`Tot(x, max=…, min=…)`) |
| 群積 | `group_mul` を 6 代数 × 4 分布（密／全正／疎／10^±40 の広レンジ）× 旗つき・旗なし、各 4,000 行 |
| 高レベル要素演算 | `ekernel_gpu` と numpy 版 `ekernel` の全 OPS（汚染値込み） |
| numpy 棚 | 全 ALGS の `rawmul` / `Lmat` / `Rmat` / `Alg.T` / `nop` 五モード × 4 演算 × 3 括弧 / `nsolve` 三面 / 全 IMPLS の `impl_tensor` |
| 超越関数 | `hyper_transcend` の `hexp` / `hlog` / `hinv` |

合わせて **685 本の配列・浮動小数 136 万要素・旗と整数 134 万要素**。

## `--negative-control` — 「一致」は検査が緩いだけでも出る

**この道具の一番大事な機能です。** 完全一致という結果は、検査が何も見ていなくても出ます。
なので作業ツリーのコピーに 1 行だけ細工した変異体を作り、比較器が**それを見つける**ことを
確かめます。見つけられなければ、壊れているのは検査の方です。

| 変異体 | 細工 | 期待 |
|---|---|---|
| `wiring` | 巡回代数の配線を `(i+j)%M → (i+j+1)%M` | 値が変わる → 26 件の差分 |
| `flag-rule` | `tot_add` の「真の零は加法単位元」則を落とす | 旗だけ変わる → `tot_add.flag` に 487/9216 件 |

`flag-rule` の方が重要です。値は 1 ビットも変わらず**旗だけ**が変わる細工を捕まえられるなら、
この検査は全域算術のいちばん壊れやすい層を実際に見ています。

変異体の定義は `ab_check.py` の `MUTANTS` にあります。細工の目印（置換前の文字列）が
見つからなくなったら、それは変異体の定義が古くなった合図で、その旨を報告して失敗します。

## self_test の種

`cuda_total.self_test()` は既定で**固定標本**（`TOTAL_ARITH_SEED=0`）を使います。数字が実行
ごとに動くと「改修で変わったのか乱数か」が判別できず回帰検査にならないためです。ただし
オラクル検査は本来ファズなので、種を変えれば別標本を回せます:

```bash
TOTAL_ARITH_SEED=1 python cuda_total.py    # 別の標本で同じ契約を検査
```

失敗したら種を添えて報告すれば、そのまま再現できます。
